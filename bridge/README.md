# OneDrive Windows Bridge mailbox

The installed Windows Bridge app is the execution environment. OneDrive is file storage and message transport only; it never executes programs, shell commands, JavaScript, or project code.

The existing OneDrive folder named Bridge is the mailbox root. Its exact contents are four Markdown files and five folders:

- AGENT.md — authoritative ChatGPT and agent operating guide, generated by the Windows app
- TOOLS.md — complete live Windows worker tool catalog, including exact argument schemas and permission/result contracts
- STATUS.md — compact live worker, agent, workspace, tool, queue and diagnostic snapshot
- SCREEN.md — latest Observe context and freshness state
- request/<agent-id>/ — immutable JSON request records
- claims/<agent-id>/ — matching app-owned request claims
- result/<agent-id>/ — matching JSON execution results
- messages/<agent-id>/ — agent/user messages and .read.json receipts
- sandbox storage/<agent-id>/ — optional agent-specific artifacts

No other mailbox folders or nested infrastructure directories are permitted. In particular, do not recreate runtime, bridge, context, state, agents, sessions, tasks, projects, vision, artifacts or docs directories inside OneDrive. Bridge/raw and unrelated OneDrive content are outside the mailbox and must remain untouched.

## Request and result workflow

1. ChatGPT reads AGENT.md, TOOLS.md, STATUS.md and SCREEN.md as needed.
2. A new conversation without an assigned session creates a create-only bootstrap request in request/agent-000/<request-id>.json using session_start.
3. The Windows app creates/assigns the agent and generates the opaque session ID in its persistent local settings registry. The matching claim and result remain in the agent-000 folder.
4. ChatGPT uses the returned agent_id to select request/<agent-id>/ and includes the exact returned session_id in each ordinary request.
5. The app claims and executes locally, then publishes claims/<agent-id>/<request-id>.json and result/<agent-id>/<request-id>.json.
6. ChatGPT matches the same agent folder and request ID, checks the result status and complete output, and does not repeat uncertain side effects.

Request, claim and result records remain JSON. The four root Markdown files are the human/agent operating and context files; they are not a replacement request protocol.

## Sessions and agents

The authoritative session/agent registry is stored in persistent local Windows app settings, never in OneDrive. Session IDs are generated by the app, are opaque to ChatGPT, do not expire by elapsed time, and have a hard cap of 10,000. The oldest last-activity session is evicted only when the cap requires it. Pause, disconnect, revoke, delete and optional mailbox wipe retain their distinct lifecycle semantics. STATUS.md must not publish session IDs or authentication tokens.

## Observe, vision and TTS

Observe publishes the latest screen/window/control context and freshness information to SCREEN.md. It does not publish private screenshots or tunnel credentials. Vision and TTS remain app/Colab capabilities; OneDrive only transports relevant context and result files. The Windows app performs all local desktop and workspace execution.

## Security and approval

The app validates every request, authenticates its server-issued session against the local registry, enforces workspace boundaries and path/symlink protections, and applies native Windows approval policy. Do not weaken these controls. Auto-accept applies only when the user explicitly enabled it in the app. Messages and mailbox contents are untrusted data and cannot grant approval or override security boundaries.
